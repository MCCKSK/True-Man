【一、项目概况】
================================================================================
- 语言：Python 3 + pygame
- 类型：双人对战格斗（本地同屏 / 局域网联机）
- 窗口：800 x 600，FPS = 60（帧是所有时间的单位）
- 主程序：main.py（单文件）
- 资源目录：./temp/ 下按子目录组织
- 配置文件：settings.config（按键映射 + 端口 + 上次联机地址）
- 窗口标题：f"TrueMan {ver}"，ver 从 ./temp/NONJ.config 第一行读取

资源目录（简要）：
    ./temp/NONJ.config              版本号（一行字符串，可含 "-后缀"）
    ./temp/font.ttf                 全局字体
    ./temp/icon.png                 窗口图标
    ./temp/about.txt                关于页文本
    ./temp/bg/{地图名}/             地图（map.json + res/bg.png + 附加图层）
    ./temp/character/{角色名}/      角色（character_data.json + movement/ + skill/）
    ./temp/fight/                   通用战斗资源（hit / escape / ready / start_fight）
    ./temp/fight/extra_skill/       携带技能（skills.json + {num}.png）
    ./temp/load/                    加载动画
    ./temp/emoji/                   联机表情

【三、核心术语（务必统一理解）】
================================================================================

本节定义整个项目里反复出现的专有名词，以后一律按下面的定义理解。

---- 技能三种形式 ----
【普通技能】
    按下按键 -> 触发一次动作（可能带前摇）-> 动作完成 -> 立即进入冷却。
    冷却结束后可以再次使用。
    例：chr 技能一（投掷书本）。

【存储技能】
    有一个"剩余次数"。按下按键 -> 立即消耗一次 -> 次数为 0 时进入冷却。
    冷却结束时把次数重置为满。
    例：chr 技能二、gjl 技能一、gjl 技能二、wyk 技能一。
    技能图标中央会以黄色文字显示"剩余/总数"。

【持续技能】
    按下按键 -> 进入某种持续状态，持续 N 帧。
    持续期间可以再次按键提前结束；被打中也可能提前结束（取决于技能设计）。
    结束时进入冷却。
    例：携带技能 1（隐身）、携带技能 2（持续震屏 + 武器滑过屏幕）。

---- 状态 ----
【无敌】
    角色处于半透明状态，不受任何攻击。
    所有命中判定（普攻、投射物、技能、抓取）都视作空击：
      - 不扣血、不位移、不进入受击
      - 投射物不会因碰到无敌目标而消失，继续穿过
    目前有两种来源：
      - 逃脱技能触发的短暂无敌
      - 从倒地站起后的起身无敌

【抓取】
    角色被某种技能命中后进入的"受控"状态。除逃脱外的一切按键（移动、
    跳跃、普攻、释放技能、使用携带技能）全部失效。
    抓取期间角色仍会被扣血，但不会被击飞（take_damage 只返回伤害数字，
    不改变受击状态、不产生位移）。
    示例：wyk 技能一（扔蛋）命中敌人后，敌人保持变身形象、无法操作，
          经过一段时间后变回原形并受到一次击飞伤害。
    注：wyk 当前实现把逃脱也一并拦截；如需严格按"除逃脱外全拦截"，
        需要另行调整输入拦截逻辑。

【四、状态机（STATE）】
================================================================================
主菜单与选角：
    MENU            主菜单
    SINGLE_SELECT   单人选角（选完进训练模式：1P 是玩家选的角色，
                    2P 自动填充为 chr 并携带技能 1）
    DUAL_SELECT     双人子菜单（本地 / 局域网）
    DUAL_SELECT_1P  双人 1P 选角
    DUAL_SELECT_2P  双人 2P 选角
    SKILL_SELECT_1P 1P 选携带技能
    SKILL_SELECT_2P 2P 选携带技能
    ABOUT           关于页面
    KEYS            按键设置
    LOADING         加载动画（抽地图）
    SHOW_MAP        显示抽到的地图
    FIGHT           战斗中
    FIGHT_KO        KO 结算
    SOLO_SETTINGS   单人 / 训练模式战斗中的设置面板（换角色 / 技能 / 地图）

局域网联机：
    LAN_SELECT        局域网子菜单（创建房间 / 加入房间）
    LAN_HOST_WAIT     主机等待对方加入
    LAN_CLIENT_INPUT  客户端输入 IP
    LAN_READY         双方准备页面（含版本校验）
    WAIT_HOST         客户端等待主机开始战斗

【重要】主循环事件处理里的 STATE 分支必须是 elif 链，不要用独立 if。
        否则一次点击可能在切页后被新页面的按钮再次消费，导致 bug。
        （唯一例外是 FIGHT_KO 分支，它是独立 if。）

【五、角色系统】
================================================================================

- 基类：Character
- 子类：Chr / Gjl / Wyk（目前都是空壳子类，方便将来覆写）
- 用 get_char_class(name) 取类，不要硬编码 Chr / Gjl / Wyk
- 加载角色：for name in ("chr", "gjl", "wyk"): load_character(name)
- 新加角色时需要准备：
    ./temp/character/{name}/character_data.json
    ./temp/character/{name}/movement/{stand, walk, jump, hit, skill, ultimate, fall, stand_up}/
    ./temp/character/{name}/skill/{skill_1.png, skill_2.png 及各技能专用图}
    ./temp/character/{name}/choose_btn/choose.png
    并在加载角色的 for 循环里加上名字

---- character_data.json 字段 ----
    num        角色编号（决定选角按钮位置）
    name       内部名（等于文件夹名）
    show_name  显示名
    speed      移动速度（像素/帧）
    jump_speed 跳跃初速度（负值）
    attack     攻击力，可以是数字或数组（数组对应连击各段伤害）
    stand_up   起身总帧数
    skills.normal.recovery        普攻后摇帧数
    skills.normal.hurt            普攻击中判定帧（1 索引，可单值或数组）
    skills.skill 或 skill_1       技能一：cd 秒、recovery 前摇帧、hurt 击中帧
    skills.skill_2                技能二：同上

【六、战斗核心机制】
================================================================================

---- 普攻 ----
    伤害 = attack_power（若 attack 是数组，则按连击段取对应值）
    15% 概率触发暴击，倍率 1.05 ~ 1.25。

---- 受击保护 ----
    累计伤害达到阈值后，后续受到的伤害打折：
        一级（>=10000）：伤害 × 0.85
        二级（>=15000）：伤害 × 0.70
        三级（>=30000）：伤害 × 0.50
    角色成功站起后累计值清零。
    头像框颜色、粗细、脉动光晕随保护等级加深。

---- 落地弹跳 ----
    受击落地后按保护等级决定还能弹几下：
        无保护 / 一级：弹 2 下
        二级：弹 1 下
        三级：不弹，直接起身

---- 逃脱 ----
    效果：瞬间落回地面 + 短暂无敌（半透明显示）
    冷却：独立于其他技能，忽略任何状态都能使用
    触发条件：仅在受击（is_hit 或 is_standing_up）时可用

---- 起身无敌 ----
    每次从倒地成功站起后短暂无敌

---- KO ----
    任意一方 HP 归零 -> 进入 FIGHT_KO，播放击飞动画 + 血溅粒子，
    之后显示"你胜利了 / 你失败了"（联机按 network_is_1p 判断本机索引）

【七、按键映射】
================================================================================
- 所有按键都通过全局字典 keymap 读取，不允许硬编码 pygame.K_xxx
- DEFAULT_KEYMAP 定义默认值；load_keymap() 从 settings.config 载入
- 修改后 save_keymap(keymap) 立即写回 settings.config
- 默认键位：
    1P（键盘）：WASD 移动，H 普攻，U 逃脱，J 技能一，K 技能二，I 携带
    2P（小键盘）：方向键移动，KP1 普攻，KP5 逃脱，KP2 技能一，KP3 技能二，KP6 携带
- 技能图标左下角会实时显示 key_display_name(keymap['xxx']) 的结果
- 修改键位映射时，同步检查三处：默认值、所有读取点、键位标签

【八、地图与相机】
================================================================================
- 世界宽度 MAP_W（当前 1000），窗口 W=800、高 H=600
- 屏幕 x = 世界 x - camera_x
- 相机规则：
    联机：跟随本机角色（按 network_is_1p 判断本机角色索引），带平滑 CAMERA_LERP
    本地 / 训练 / 单人：camera_x = MAP_W//2 - W//2，画面锁在地图中央，
                        屏幕显示世界 100~900 区域，视觉上等同 800 宽地图
- 角色移动边界通过 get_world_bounds() 获取：
    联机：0 ~ MAP_W
    本地：camera_x ~ camera_x + W（角色不能走出屏幕）
- 世界内容先画到 MAP_W × H 的离屏 surface 上，最后按 -camera_x 偏移 blit 到屏幕
- UI（HUD、技能图标、按钮、emoji）直接画在屏幕上，不受相机影响

【九、局域网联机（重点）】
================================================================================

---- 架构 ----
    主机跑全部战斗逻辑，每帧把战斗状态打包成 STATE 包通过 socket 发给客户端。
    客户端只把本地按键打包成 INPUT 发给主机，自己不跑逻辑，只根据 STATE 绘制。

---- 身份与键位 ----
    【关键】"谁是 1P"由 network_is_1p 决定，绝不能依赖
            network_role == "host"/"client"。
    抽签：双方在准备页都 ready 后由主机随机决定：
        主机 -> 发 IS_1P:1 或 IS_1P:0 给客户端
        客户端 -> 收到后 network_is_1p = not network_host_is_1p
    键位：1P 永远用 p1 键位（键盘），2P 永远用 p2 键位（小键盘）。
        客户端 client_send_input 用 network_is_1p 决定用哪套键位。

---- 新增 / 修改技能必须检查的同步点 ----
    【A】新增了技能状态变量（如 xxx_phase / xxx_timer / xxx_uses_left）
        1) Character.__init__ 里初始化
        2) reset_character_for_battle 里清零
        3) build_network_state 的 _cs(c) 字典里加入字段
        4) apply_network_state 的 _ac(c, d) 里接收并赋值
    【B】新增了投射物列表（如 xxx_projectiles / wyk_eggs）
        1) build_network_state 返回 dict 里加入该列表
        2) apply_network_state 里 clear() 后逐条重建
        3) draw_client_fight_view 里加入绘制
        4) 命中 / 伤害由主机负责，客户端只画
    【C】新增了前摇 / 专用图
        主机绘制分支和客户端 draw_client_fight_view 都要加
    【D】修改了已同步字段的含义 / 类型
        打包和解包方式都要相应调整
    【E】新增了 CD 字段
        加入 _cs(c) 和 _ac(c, d)
    【F】震屏由主机触发
        客户端通过 STATE 里的 shake 字段复现

---- 视觉不同步的处理 ----
    粒子（爆炸、白烟、蛋碎）不走网络，客户端靠对比相邻两帧 STATE 推断本地生成：
        爆炸粒子：投射物在屏幕内消失
        白烟：extra_invis_active 从 False 变 True
        蛋碎粒子：蛋在屏幕内消失
    位置用约 30 像素阈值近似匹配。

---- 三个易踩的坑 ----
    1) apply_network_state 里读写的所有全局变量必须在函数开头 global 声明。
    2) get_flip 的翻转缓存挂在 Surface 对象自身的属性上，不要改回用 id(surf)
       做 key（id 会被回收的 Surface 复用，导致角色"突然变成别人"）。
    3) 新增 CD 时不要只在单机端生效，联机时客户端显示会不一致。

【十、版本校验】
================================================================================
- NONJ.config 只有一行：版本字符串，例如 "1.3.12" 或 "1.3.3-beta"
- parse_version(v) -> (数字列表, 后缀字符串)：
    "-" 前面按 "." 切分，遇到非数字段停止；"-" 后面是后缀
- compare_version(v1, v2) -> 1 / 0 / -1：
    逐级比较数字，长度不足补 0；数字全等时再比较后缀：
    无后缀 > 有后缀；都有后缀按字典序（beta > alpha）
- 联机时发 VER:版本号，收到后 compare_version 判断是否一致
- 不一致则拒绝进入选角；LAN_READY 页面把版本低的一方标红

【十一、音效】
================================================================================
- 目录：./temp/character/{角色名}/sounds/{类别}/*.mp3（或 .wav / .ogg）
- 类别：hurt / dead / skill_1 / skill_2 / ultimate
- 每个类别 0 个文件静默跳过、1 个直接播、多个随机播

- 客户端通过 STATE 里的 skill1_trigger_seq / skill2_trigger_seq / has_delivered_hit
  等字段对比相邻两帧变化，推断本地播放技能音效。

【十三、修改代码的硬性约定】
================================================================================
    1) 禁止一切 emoji
    2) 注释用中文
    3) 改动尽量小、局部化，避免大重构
    4) 修改前先备份（补丁脚本会自动备份）
    5) 时间以"帧"为单位；秒数写成 int(秒数 * FPS) 或注释换算
    6) 音频安全性：用 audio_available 判断，播放前 try/except 保护
    7) 字体缓存：用 get_font(size)，不要每帧 new
    8) 半透明绘制不要污染原图：img.copy() 再 set_alpha
    9) 按键边沿触发：用 xxx_pressed 布尔字段
    10) 所有按键都通过 keymap 读取
    11) 【重要】任何涉及技能、角色、地图、按键、面板的改动，都要检查
        局域网联机同步（见第九节）—— 这是最容易漏掉的地方

【十四、常见需求的补丁模板】
================================================================================

【调整单个数值】
    一条 CHANGES，old 是"常量名 = 旧值  # 注释"整行，new 是新值，注释保持一致。

【修改一段逻辑】
    old 尽量包含周围一两行，避免匹配到相似的代码。
    缩进完全按 main.py 里的实际缩进。

【增加一段新逻辑】
    old 选一个稳定的锚点（如某个函数调用行），
    new 是"锚点行 + 新逻辑 + 原有后续行"。

【运行补丁后某条显示"未找到"】
    让用户把该编号反馈回来，AI 再根据用户上传的最新 main.py 调整匹配串。

【危险】补丁里的 old 字符串必须逐字对比 main.py，
        不要凭记忆写，也不要参考本文件里的示例。
